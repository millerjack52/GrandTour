FloraTrail: separate tree-tip movement from rooted undergrowth bending
==================================================================
16 November 2026. STATUS: v4 candidate and fresh verification completed, both
with process exit zero. Motion Preview now opens v4 for interactive review.
The normal driving launchers and LiDAR remain unchanged. A sustained driving
60 fps result and final user approval of the animation are still outstanding.

User finding
The actual v2 preview barely moves the tree leaves and the bushes animate badly.
The earlier description of subtle movement was not sufficient visual acceptance.
The same generic vertex wave was applied to both families: a 3 cm tree offset
and a spatially varying faster flutter on bushes. A whole-tree height mask also
attenuated nearby lower branches. Increasing only the nominal amplitude would
not fix that masking or the undergrowth's deformation style.

Implemented candidate changes
- Broadleaf canopy amplitude control 12 cm; pine 10 cm. These are maximum input
  controls, not measured screen displacement. Coherent gusts and smaller lateral
  tip flutter replace the previous local-position high-frequency field.
- The v4 canopy mask acts above the lowest tenth of mesh height, with a minimum
  35 percent interior influence and stronger outside influence. Only leaf
  materials deform; the bark mesh is unchanged. This is an approximation using
  mesh bounds, not per-leaf pivots or an authored branch skeleton. Attachment
  quality still needs broader review; the fixed-camera captures now show
  readable nearby lower-branch motion where v2/v3 barely moved.
- Shrubs and ferns bend slowly around an instance-space base transformed to
  world space. The offset is rotational, height weighted and anchored at the
  bottom, with no fast per-vertex flutter. Controls: shrub 1.8 cm, fern 1.4 cm,
  grass 1.6 cm, dry grass 1.2 cm; rotation limited to .06 radians.
- Foliage colours, masks, normal/roughness outputs and source textures are
  unchanged. Falling leaves retain the existing count, shapes and animation.
- Test static shadow proxies separately from visible wind. Only components
  that originally cast shadows get proxies. They reuse the same mesh, original
  materials, instance transforms and LOD assets, disable WPO, main/depth-pass
  rendering, collision, ray tracing and distance-field lighting. Visible wind
  components stop casting shadows; baseline profiling restores their original
  materials/shadows and hides proxies. This duplicates shadow instances, not
  visible foliage. Fixed-view render cost and GPU memory headroom were measured
  below; wider visibility conditions and full driving remain unverified.

v3 attempt and why it was not accepted
v3 compiled, saved and reloaded successfully inside the candidate process.
Surface connections, lighting, ground, flat water and visible geometry checks
passed. Four shadow-only components contained 2,843 instances: 159 ferns,
92 pines, 2,524 shrubs and 68 broadleaf trees. Original mesh/material/transform
relationships were audited. All 159 planned still/animation captures completed.
The first v3 canopy mask (.12-.70 height) still held too much of nearby lower
foliage still. This led to the wider v4 influence described above; v4 is not
represented by the v3 captures.

The v3 run started at 16:48:24 America/Edmonton time; Wardogs started at 16:48:57, after
preflight, while Unreal was building the candidate. At the first timing window
only 20 frames were captured and every sampled frame exceeded the GPU memory
budget; minimum headroom was -1646.8 MB. The analyzer rejected the window for
insufficient frames. This is not a valid before/after performance measurement
and cannot prove either a shadow saving or an intrinsic v3 slowdown.
The engine exited zero, but report.ok was false: the test FAILED. The user game
was left untouched. No second renderer was launched while it was running.

v4 also copies/checks original component instance-cull distances on the shadow
proxies; this addition passed in v4 candidate and fresh saved verification.
v3's original mesh LOD assets were retained, but the pending cull-distance audit
must not be retrospectively counted as a v3 pass.

Resource handling
Preflight now refuses a running Wardogs process even if RAM briefly appears
sufficient. Runtime checks before installation, capture groups and profiling
windows detect a game launched after preflight. GPU memory over-budget frames
invalidate timing comparisons. Checks do not terminate user applications.
The preflight refusal was exercised with Wardogs running: no Unreal was started.
